# Почему настройка не идёт из Claude Code на web

Дата проверки: 2026-08-18. Среда: `env_0194jJrSmsKd1Szp9vBeQ7yY` (Default,
`anthropic_cloud`).

Скилл `hermes-vps-setup` целиком построен на `ssh hermes-vps "..."`. Из облачной
песочницы Claude Code это невозможно. Ниже — что именно проверено.

## 1. Прямой SSH на 22 порт — таймаут

```
$ ssh -v -o ConnectTimeout=15 root@<IP> true
debug1: Connecting to <IP> port 22.
debug1: connect to address <IP> port 22: Connection timed out
```

Сырой TCP подтверждает то же:

```
$ timeout 8 bash -c 'cat </dev/null >/dev/tcp/<IP>/22'   # rc=124 (таймаут)
$ timeout 8 bash -c 'cat </dev/null >/dev/tcp/<IP>/2222' # блокировано
```

Исходящий трафик песочницы разрешён только на 80 и 443.

## 2. SSH через HTTP-прокси песочницы — туннель открывается, но данные не идут

Прокси (`$HTTPS_PROXY` = `http://127.0.0.1:43915`) отвечает `200 Connection
Established` на CONNECT для любого порта — но это оптимистичный ответ, реального
релея не происходит:

```
$ ssh -o "ProxyCommand=nc -X connect -x 127.0.0.1:43915 %h %p" git@github.com
kex_exchange_identification: Connection closed by remote host
```

Контрольный тест: `nc -X connect -x 127.0.0.1:43915 github.com 22` не возвращает
SSH-баннер, хотя github.com:22 его точно отдаёт. Прокси инспектирует TLS и рвёт
поток, который не начинается с TLS ClientHello. SSH таким не является.

## 3. Порты 80/443 на сервере — пусто

```
$ curl -i http://<IP>/
HTTP/1.1 503 Service Unavailable
upstream connect error or disconnect/reset before headers...
```

503 отдаёт Envoy самой песочницы: соединение до апстрима (реального сервера)
не установилось. То есть на 80/443 сервера ничего не слушает — переносить туда
sshd как обходной путь тоже не выйдет без доступа к серверу (замкнутый круг),
а даже с ним поток сломает TLS-инспекция из п.2.

## Вывод

Обходного пути внутри этой среды нет. Настройку нужно вести из окружения с
полноценным исходящим SSH:

1. **Claude Code локально** (CLI или десктоп-приложение) на своей машине —
   рекомендуемый вариант, скилл отработает целиком без изменений.
2. **Веб-консоль хостера** (VNC/recovery) — команды из скилла выполняются вручную,
   медленно, но работает.
3. Возможно, окружение Claude Code с менее строгой сетевой политикой — сетевая
   политика выбирается при создании окружения, см.
   https://code.claude.com/docs/en/claude-code-on-the-web
   Гарантий нет: даже «полный доступ» может остаться HTTP-прокси-медиированным,
   и тогда SSH снова не пройдёт. Проверять тестом из п.1.
