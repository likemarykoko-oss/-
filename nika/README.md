# Ника — вторая инсталляция Hermes на 216.57.111.124

Отдельный Telegram-бот с личностью «Ника» (цифровой рекрутёр студии «Мэри КО-КО»)
рядом с боевым `hermes-gateway`, без пересечений в рантайме.

## Как запустить

На сервере, от root:

```bash
curl -fsSL https://raw.githubusercontent.com/likemarykoko-oss/-/claude/telegram-avito-agent-hm8j1p/nika/install-nika.sh -o /root/install-nika.sh

bash /root/install-nika.sh --dry-run    # 1. проверка, ничего не меняет
bash /root/install-nika.sh              # 2. установка
```

Скрипт задаст ровно два вопроса: токен от @BotFather (ввод скрыт, в лог не
попадает) и числовой user id владелицы — его он умеет определить сам,
если написать боту любое сообщение.

Опции: `--soul telegram` (смягчённый промпт), `--add-swap`, `--uninstall`, `--help`.

## Что получится

| | боевой Hermes | Ника |
|---|---|---|
| код | `/usr/local/lib/hermes-agent` | `/opt/hermes-nika` |
| данные | `/root/.hermes` | `/opt/hermes-nika-home` |
| сервис | `hermes-gateway` | `hermes-nika-gateway` |
| A2A | `127.0.0.1:9900` | `127.0.0.1:9901` |
| CLI | `hermes` | `hermes-nika` |
| provider | Codex (OAuth) | **OpenRouter** |
| модель | — | `minimax/minimax-m3:free` + запасная цепочка |
| голос/STT | есть | не ставится |

Данные Ники лежат рядом с кодом, а не внутри него, и это не вкусовщина: апстрим-
установщик раскладывает managed `uv` в `$HERMES_HOME/bin` **до** клонирования
репозитория в `--dir`, а затем требует, чтобы `--dir` был либо git-репозиторием,
либо пустым. При вложенной раскладке он сам себе мешает и падает.

## Защита боевого бота

Сервер маленький (1 CPU / 2 ГБ), боевой бот на нём уже работает. Поэтому:

- **Codex не подключается никогда.** Его refresh-токен одноразовый: повторный
  логин того же аккаунта оторвал бы авторизацию у боевого бота. Из боевого
  `.env` переносятся только `OPENROUTER_API_KEY` и ключи GonkaRouter/Nous;
  перед записью скрипт проверяет, что в новый `.env` не просочилось ничего
  с `CODEX`/`OPENAI`/`CHATGPT`, и падает, если просочилось.
- **Лаунчер `/usr/local/bin/hermes` защищён.** Он сохраняется до установки, и
  если установщик его перезапишет — восстанавливается, а новый становится
  `hermes-nika`.
- **Голосовой стек не ставится** (`--skip-browser`, `--skip-computer-use`,
  `--ensure node,ripgrep` — без ffmpeg), плюс `MemoryHigh=600M` /
  `MemoryMax=900M` в юните, чтобы Ника не выдавила боевой процесс в OOM.
- **Порт проверяется до установки.** Если 9901 занят — скрипт остановится.
- **Личность боевого бота** (`/root/.hermes/SOUL.md`) проверяется первым делом;
  восстановление из бэкапа — только после явного «да», с бэкапом текущего
  файла. Копии с `nika-recruiter` в имени исключены из кандидатов.
- В конце скрипт проверяет, что `hermes-gateway` всё ещё `active`.

Флаги установщика подбираются по его же `--help`: если какого-то флага в этой
версии нет, он не передаётся.

## Что доступно в API Авито на текущем тарифе

Проверено живыми запросами, а не по документации:

| запрос | ответ | что это даёт |
|---|---|---|
| `/core/v1/items` | 200 | свои объявления: id, заголовок, цена, адрес, ссылка, статус |
| `/core/v1/accounts/{u}/items/{id}/` | 200 | `finish_time` — когда объявление снимется |
| `/core/v1/accounts/{u}/balance/` | 200 | баланс кошелька (`real` + `bonus`) |
| `/messenger/v2/accounts/{u}/chats` | 200 | по кому чат, кто написал последним, когда, цена из объявления |
| `/messenger/v3/.../messages/` | **402** | текст переписки — за подпиской |
| `job/v1/applications/get_ids` | **402** | отклики Авито.Работы — за Максимальной подпиской |

Ключевое: **метаданные чатов открыты, а текст закрыт**. Значит, «кому-то не
ответили — вот ссылка» сделать можно, а «прочитать и ответить» нельзя.

Цену берём из `price_string` карточки объявления в чате, а не из `price`
в `/core/v1/items`: второй отдаёт `72500` там, где в объявлении написано
«60 000 — 85 000 ₽», и называть кандидату это число нельзя.

## Два фоновых процесса

`nika-avito-sync` (таймер, раз в 6 часов) — кладёт объявления студии в
`SOUL.md` между маркерами `AVITO:BEGIN/END`, остальной промпт не трогает.

`nika-avito-watch` (таймер, раз в 15 минут) — сторожит и пишет в Telegram,
когда есть повод: баланс ниже порога, объявление скоро снимется, объявление
пропало из активных, кандидату не ответили дольше получаса. Отправляет через
`hermes send`, то есть **без обращения к модели** — оповещения бесплатны.
Состояние в `avito-watch-state.json`, поэтому одно и то же не повторяется.
Имя кандидата попадает в текст только при `parsing_allowed: true`.

Пороги: `NIKA_BALANCE_FLOOR` (500 ₽), `NIKA_EXPIRY_DAYS` (3 дня),
`NIKA_REPLY_GRACE_MIN` (30 минут), `NIKA_MAX_LIST` (8 строк),
`NIKA_ALERT_CHAT` (куда писать; по умолчанию первый из `TELEGRAM_ALLOWED_USERS`).
Посмотреть без отправки: `NIKA_WATCH_DRY_RUN=1 nika-avito-watch`.

## Модель и запасная цепочка

Апстрим-установщик оставляет в `config.yaml` **платную** модель. На ключе
владелицы это прямые деньги, поэтому установщик проверяет `model.default` и,
если там не `:free`, ставит проверенную бесплатную. Уже сделанный вручную
выбор он не трогает.

Бесплатный пул OpenRouter отдаёт `429`, и агент по умолчанию просто ждёт
минуту — в переписке с кандидатом это заметно. Поэтому пишется
`fallback_providers`. Ступени намеренно идут через **разные апстримы**: общий
лимит накрывает все модели одного провайдера разом, так что запасная модель от
того же апстрима бесполезна.

Переопределяется переменными окружения: `NIKA_MODEL_DEFAULT`,
`NIKA_FALLBACK_1`, `NIKA_FALLBACK_2`.

Посмотреть цепочку: `hermes-nika fallback list`.

## Откат

```bash
bash /root/install-nika.sh --uninstall
```

Удаляет сервис, `/opt/hermes-nika` и обёртку `hermes-nika`. Боевую инсталляцию
не трогает. Бэкапы лежат в `/root/.nika-install-backup`.

## Отчёт

После установки — `/root/nika-report.txt`: статусы сервисов, память, порты,
юнит, `.env` со скрытыми значениями, `config.yaml` со скрытыми секретами,
журнал (токены в нём вымараны) и список бесплатных моделей. Секретов там нет,
файл можно присылать целиком.

## Промпт

Два варианта, выбираются флагом `--soul`:

- `avito` (по умолчанию) — текст из брифа **дословно**, посимвольно сверен;
- `telegram` — тот же текст плюс блок в начале: интеграции с Авито ещё нет,
  не ссылаться на объявления, которых не видно, не выдумывать баланс и статусы.
  Остальная логика (анкеты, карточки управляющей, окна у админов, эскалации)
  не меняется — она и так работает в Telegram.

## Что дальше

Прямая интеграция с Авито (Messenger API, вебхуки `POST /messenger/v3/webhook`)
намеренно **не реализована**. Разведка сделана, ключи `AVITO_CLIENT_ID` /
`AVITO_CLIENT_SECRET` / `AVITO_USER_ID` лежат в `/root/.hermes/.env`. Начинать
только по отдельному запросу, после обкатки личности в Telegram.

## Осторожно

Этот репозиторий **публичный**, поэтому в него не попадает ничего секретного:
ни токенов, ни ключей, ни user id. Текст промпта Ники (адрес студии, график,
регламенты) в скрипте есть — если он не должен быть публичным, скажи, и мы
либо сделаем репозиторий приватным, либо будем доставлять промпт отдельным
файлом мимо git.
